## Problem Statement

Four small divergences, each to be made identical on both branches:

- `bin/alert`: a symlink on main, a regular file on svelte (changed
  2026-09-10). Find what each is and which is current; most likely svelte's
  file supersedes the symlink's target. Check nothing else on main depends

  Union where the contents differ.

## Decisions

- `bin/alert`: svelte's file. Svelte never had the symlink. Its `d47ccda`
  (2026-09-10) says it replaces the per-machine symlink to an `alert-*`
  script on purpose and leaves `alert-slack` as a manual call. Main's
  callers (`bin/gh-pr-undraft`, `.claude/` docs and permissions) pass a
  message as arguments, which svelte's script accepts. Its helpers
  (`exists`, `alert-hterm`, `alert-slack`) are byte-identical on both.
- `bin/alternatives/.gitignore`: svelte's. In a test repo, main's `./`
  ignored nothing. Svelte's `*` does what main's comment meant, and
  `!alternatives` keeps svelte's tracked choices visible.
- `bin/brew`: **deviation from the brief.** I kept main's line without a
  guard and added a two-line comment. A `[ -d ]` guard behaves exactly
  like no guard: where the directory is missing, PATH lookup skips it, and
  where it exists, both versions put it on PATH. So the line already does
  nothing on other hosts, and the guard would be extra code with no
  effect. Moving it into `.config/sh` would put ruby26 on every shell's
  PATH, where today it applies only to the brew call.
- `.envrc`: union. Svelte's lines come first, then main's
  `GIT_DISCOVERY_ACROSS_FILESYSTEM=1` with its comment. It is harmless off
  WSL. Main's copy had no final newline; the merged file has one.
