# claims.kb — maintenance guide

The ledger of commitments about how work gets done under `~/.claude`.
`../claims.md` is the entry point. Each child is a theory: `X.md`
stipulating an ontology beside `X.kb/` holding the claims confined to it.

## What belongs here

A commitment whose reversal would change how an agent or the operator
acts, and which is worth more than the cost of re-deriving it: a measured
regularity, a decision rule, a rate that took real work to establish.

## What does NOT belong here

- Instructions — a skill, a must-read entry, or `CLAUDE.md` text. Those
  are directives; nothing about them is contestable in the way a claim
  is. The tell is `standing:` — if the honest value is `user` for every
  file in a collection, it is a manual, not a theory.
- Anything scoped to one repository. It belongs in that repository.
- A narrative of what happened. That is `../devlog/`; a claim cites it.

## Adding a theory

A new theory earns its directory when its claims need words the existing
theories do not coin, or when two existing theories both lean on the same
subsection of a third. Never merely because a collection got long.
